# 个人智能穿搭推荐软件

## 1. 项目概述

开发一个**个人使用的智能穿搭推荐软件**。

软件根据用户自己的衣物信息，以及当天/未来天气、星期、节假日、使用场景、用户历史穿着记录、用户喜欢/不喜欢的反馈等信息，自动生成个性化穿搭推荐。

核心目标：

> 每天打开软件，可以快速得到“今天穿什么”的推荐，并且软件能够通过用户的反馈逐渐了解用户的穿衣偏好。

软件主要服务于**单个用户**，暂不考虑多用户、社交、电商、支付等复杂功能。

---

# 2. 核心使用流程

软件核心流程：

```text
用户建立个人衣橱
        ↓
录入衣服
        ↓
获取天气
        ↓
判断日期 / 星期 / 节假日
        ↓
用户选择或自动判断场景
        ↓
推荐引擎生成穿搭
        ↓
展示 3~5 套穿搭
        ↓
用户选择：
  喜欢
  不喜欢
  换一批
        ↓
记录用户反馈
        ↓
调整个人偏好权重
        ↓
下一次推荐更加符合用户习惯
```

- 大规模用户推荐系统

# 4. 产品定位

这是一个：

> **个人 AI 衣橱 + 天气感知 + 个性化穿搭推荐工具**

不是服装电商，也不是社交平台。

所有推荐优先使用：

> **用户自己的衣服**

如果用户衣橱中没有合适衣服，可以明确提示：

> “当前衣橱中没有非常匹配的组合。”

不要虚构用户不存在的衣服。

# 10. 天气数据转换

不要让推荐算法直接依赖具体温度。

需要先转换成“穿衣环境”。

例如：

```text
< 5℃      极冷
5~10℃     寒冷
10~15℃    偏冷
15~20℃    凉爽
20~25℃    舒适
25~30℃    偏热
30~35℃    炎热
> 35℃     酷热
```

这个范围应该做成配置，而不是写死。

例如：

```json
{
  "cold": 10,
  "cool": 15,
  "comfortable": 25,
  "hot": 30,
  "very_hot": 35
}
```

# 20. 防止重复推荐

推荐系统需要考虑最近穿着历史。

建议：

```text
今天刚穿过：
强烈降低权重

最近3天穿过：
降低权重

最近7天穿过：
轻微降低权重

超过7天没穿：
适当提高权重
```

但是：

> **不能完全禁止重复。**

如果用户衣服很少，应该允许重复。

# 21. 推荐算法 V1

第一版不要使用复杂机器学习。

使用**规则 + 权重评分**。

总评分：

```text
总分 =
天气匹配
+ 场景匹配
+ 个人喜好
+ 颜色搭配
+ 风格匹配
+ 最近穿着
+ 季节匹配
+ 随机探索
```

建议权重：

```text
天气匹配       30%
场景匹配       20%
个人偏好       20%
颜色搭配       10%
风格匹配       10%
穿着历史        5%
随机探索        5%
```

权重必须配置化。


# 25. 推荐探索机制

不能因为用户喜欢黑色，就永远只推荐黑色。

系统需要保留一小部分“探索”。

例如：

```text
80%：
按照用户历史偏好推荐

20%：
尝试用户较少使用的颜色/风格
```

这样可以逐渐发现用户潜在喜欢的风格。

# 37. 推荐系统必须避免的问题

Agent 开发时重点测试：

### 问题 1

夏天推荐羽绒服。

→ 必须避免。

### 问题 2

冬天推荐短裤。

→ 必须避免。

### 问题 3

用户根本没有这件衣服。

→ 绝对不能推荐。

### 问题 4

换一批还是完全一样。

→ 必须降低重复。

### 问题 5

用户连续三天穿同一件衣服。

→ 应降低推荐权重。

### 问题 6

用户明确不喜欢某件衣服。

→ 后续推荐中降低该衣服权重。

### 问题 7

为了个性化导致天气不适配。

→ **天气适配优先级必须高于个人喜好。**

---

# 38. 推荐优先级

最终原则：

```text
天气安全
    ↓
场景合理
    ↓
季节合理
    ↓
个人偏好
    ↓
颜色搭配
    ↓
穿着频率
    ↓
探索
```

也就是说：

> 用户喜欢短袖 ≠ 10℃就推荐短袖。

系统应该：

> 尊重用户偏好，但不能违反基本穿衣逻辑。


# 40. 后续 AI 版本

MVP 完成以后，再增加：

```text
AI 图片识别衣物
        ↓
AI 自动补全衣物属性
        ↓

        ↓

        ↓
```

例如用户直接输入：

> “明天要和朋友吃饭，天气15度左右，不想穿得太正式。”

系统解析：

```text
日期 = 明天
温度 ≈ 15℃
场景 = 聚餐
正式程度 = 低
```

再调用推荐引擎。

## 给 Agent 的最重要原则

可以把下面这段直接放到 `AGENTS.md`：

```text
这是一个个人智能穿搭推荐软件。

开发目标不是构建一个复杂的电商或社交平台，而是实现一个稳定、简单、
可扩展的个人衣橱推荐系统。

核心功能：

1. 衣橱管理
2. 天气获取
3. 日期/星期/节假日判断
4. 场景判断
5. 穿搭组合生成
6. 推荐评分
7. 喜欢/不喜欢反馈
8. 换一批
9. 穿着历史
10. 个性化推荐

开发原则：

1. 优先实现 MVP，不擅自扩大需求。
2. 推荐必须优先使用用户实际拥有的衣物。
3. 推荐必须符合天气和场景。
4. 用户喜欢/不喜欢必须影响后续推荐。
5. 最近穿过的衣服应降低重复推荐概率。
6. “换一批”不能简单随机，必须保持天气和场景合理。
7. 推荐算法必须独立于 UI 和 API。
8. 推荐权重、温度区间、颜色规则等必须配置化。
9. 不要在第一版引入不必要的机器学习系统。
10. 所有核心逻辑需要有单元测试。
11. 所有外部 API 都需要考虑失败、超时和缓存。
12. 数据库设计需要考虑未来扩展 AI 图片识别和机器学习。
13. 代码必须优先考虑可维护性和可读性。
```

**我建议你下一步直接让本地 Agent 按这份规格开始做，但先不要让它一次性把所有代码写完。** 最合适的是让它先输出 `技术方案 + 项目目录 + 数据库 ER 设计 + API 设计`，你确认后再让它进入编码阶段。这样能明显减少 AI Agent 后面返工。
